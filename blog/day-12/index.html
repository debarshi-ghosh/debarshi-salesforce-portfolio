Trigger Best Practices: Bulkification and Handler Patterns

Understand the difference between structured SOQL queries and text-based SOSL search, with Apex examples, decision guidance and practical use cases.

Apex triggers execute in response to record changes. Use before triggers to validate or modify incoming records and after triggers for work requiring saved record IDs.

Trigger events and context

Events include insert, update, delete and undelete. Trigger.new and Trigger.old contain records when available; newMap and oldMap provide ID lookups. Before insert has no newMap. Delete has no Trigger.new. Undelete is after-only. After-trigger records are read-only.

trigger AccountTrigger on Account (before insert, before update, after update) {
    if (Trigger.isBefore) {
        for (Account a : Trigger.new) {
            if (String.isBlank(a.Description)) {
                a.Description = 'Pending review';
            }
        }
    }
}

Bulkification and handlers

Use one trigger per object and delegate to a handler. Process collections, query once outside loops, and perform DML on collections. Trigger batches can contain 200 records.

trigger AccountTrigger on Account (after update) {
    AccountHandler.afterUpdate(Trigger.new, Trigger.oldMap);
}
public class AccountHandler {
    public static void afterUpdate(List<Account> records,
                                   Map<Id, Account> oldMap) {
        Set<Id> changed = new Set<Id>();
        for (Account a : records) {
            if (a.Name != oldMap.get(a.Id).Name) changed.add(a.Id);
        }
        if (changed.isEmpty()) return;
        List<Contact> contacts = [
            SELECT Id, AccountId, Description FROM Contact
            WHERE AccountId IN :changed
        ];
        for (Contact c : contacts) {
            c.Description = 'Account name changed';
        }
        update contacts;
    }
}

Use field-change detection rather than a blanket static Boolean recursion guard. Consider idempotency, sharing and CRUD/FLS requirements, row limits and asynchronous processing for high fan-out. Test 200 records, unchanged values, failures and repeated execution.
