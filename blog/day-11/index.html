Apex Triggers: Context Variables and Execution Lifecycle

Understand the difference between structured SOQL queries and text-based SOSL search, with Apex examples, decision guidance and practical use cases.

Intermediate15–20 min readUpdated: November 2026

Apex triggers execute in response to record changes. Use before triggers to validate or modify incoming records and after triggers for work requiring saved record IDs.

Trigger events and context

Events include insert, update, delete and undelete. Trigger.new and Trigger.old contain records when available; newMap and oldMap provide ID lookups. Before insert has no newMap. Delete has no Trigger.new. Undelete is after-only. After-trigger records are read-only.

trigger AccountTrigger on Account (before insert, before update, after update) {
    if (Trigger.isBefore) {
        for (Account a : Trigger.new) {
            if (String.isBlank(a.Description)) {
                a.Description = 'Pending review';
            }
        }
    }
}

Execution lifecycle

Validation and before-save automation precede before triggers. Records are saved provisionally, after triggers execute, and subsequent automation can cause further updates. Commit occurs only after the transaction succeeds. Post-commit asynchronous work runs separately. Never assume a trigger executes only once.

Context variables

Use Trigger.isInsert, isUpdate, isDelete, isUndelete, isBefore and isAfter to route logic. Compare oldMap and new records to detect meaningful changes. Trigger.size is the current batch size, not necessarily the entire operation.

Practice and interview questions

Test insert, update and delete contexts, 200 records, and repeated updates. Why is newMap unavailable before insert? When should addError be used? Why can automation re-enter a trigger?
